# 智能鱼缸控制器设计文档

- 项目：SmartAquariumController
- 版本：1.0
- 日期：2026-11-20
- 目标平台：ESP32-S3 N16R8 / MicroPython 1.29 / LVGL 9.3
- 验证状态：**LVGL 界面已上板验证（六页渲染 + 性能回归通过）；硬件控制功能仍按第 14 节上板清单逐项确认**

## 1. 项目目标

实现一个可独立运行的智能鱼缸控制器，提供：

- ST7796U 480×320 横屏 LVGL 图形界面。
- 手机优先的 Web 管理与配网界面。
- 4 路独立 LED、25 kHz PWM 调光与日光节律。
- 水泵、气泵独立 PWM 调速。
- 1 路 PWM 加热，使用 NTC 水温闭环控制。
- TDS、电导率、水温、环境温湿度和高低水位检测。
- 默认 10 分钟的喂鱼模式，喂鱼期间双泵关闭。
- DS3231 硬件 RTC、NTP 校准和断网连续运行。
- BTree 数据库持久化与可配置的断电续行。
- WiFi STA、自动重连、配置 AP、NTP 校时。

不包含主动散热、风扇、水冷、自动补水、云端服务和功率设计。

## 3. 硬件接口

### 3.1 引脚分配

| 功能 | GPIO | 接口说明 |
| --- | --- | --- |
| LCD_SCK | 18 | SPI2 CLK |
| LCD_MOSI | 9 | SPI2 MOSI |
| LCD_MISO | 16 | SPI2 MISO，仅供显存读出 |
| LCD_CS | 15 | LCD 片选 |
| LCD_DC | 10 | 数据/命令 |
| LCD_RST | 11 | 屏幕复位 |
| LCD_BL | 17 | PWM 背光，高电平点亮 |
| SDA | 8 | I²C1，FT6336U、HDC1080、DS3231 |
| SCL | 3 | I²C1 |
| LED1～LED4 | 4 / 5 / 12 / 13 | 4 路独立 PWM，25 kHz |
| 水泵 PWM | 14 | 独立调速 |
| 气泵 PWM | 21 | 独立调速 |
| 加热 PWM | 7 | 独立加热控制 |
| TDS_TX | 1 | ESP32 UART1 TX → 模块 RX |
| TDS_RX | 2 | ESP32 UART1 RX ← 模块 TX |
| 高水位 | 47 | 数字输入、内部下拉、高电平有效 |
| 低水位 | 38 | 数字输入、内部下拉、高电平有效 |
| 预留/复用 | 48 | 板载 RGB LED，可复用但初版不占用 |
| 预留 | 6 | SD_CS；不启用 SD 时可释放 |
| USB | 19 / 20 | 原生 USB，不分配 |
| 日志串口 | 43 / 44 | UART0，不分配 |

N16R8 的 GPIO35～37 为 Octal PSRAM 占用；39～42、0、45、46 不作为本项目的普通扩展接口。

### 3.2 I²C 地址

- FT6336U：`0x38`。
- HDC1080：`0x40`。
- DS3231：`0x68`。
- 默认总线频率 100 kHz，公共地，3.3 V 逻辑。

### 3.3 PWM 通道预算

| 输出 | 数量 |
| --- | ---: |
| LED1～4 | 4 |
| 水泵、气泵 | 2 |
| 加热 | 1 |
| 屏幕背光 | 1 |
| 合计 | 8/8 |

不再增加蜂鸣器、第 5 路 LED 等 PWM 输出。所有 PWM 对象只初始化一次，运行中原地修改占空比。

### 3.4 水位真值表

两个传感器均为高电平有效，输入使用内部下拉。

| 高水位 GPIO47 | 低水位 GPIO38 | 判定 |
| ---: | ---: | --- |
| 0 | 0 | 缺水，报警并关闭加热 |
| 0 | 1 | 正常水位 |
| 1 | 1 | 高水位提示 |
| 1 | 0 | 组合异常，报警并关闭加热 |

采用 0.3～0.5 秒连续一致采样防抖，初版默认连续 5 次、10 Hz 采样一致后生效。

## 4. 软件分层

```text
boot.py / main.py
        │
        ├── BSP 与驱动：ST7796U、FT6336U、HDC1080、TDS、DS3231、GPIO/PWM
        │
        ├── 领域控制：数据库、时间、WiFi、灯光、双泵、加热、喂鱼、总控
        │
        ├── LVGL：480×320 横屏六页、手势、自动回主页
        │
        └── Web：手机页面、JSON API、WiFi 配置 AP
```

依赖规则：

- BSP 只封装硬件，不包含业务决策。
- 领域对象只保存状态、计算目标，不依赖 LVGL 或 HTML。
- LVGL/Web 只读取统一状态快照、提交命令，不直接访问 GPIO、PWM 或数据库。
- 主循环是配置提交、模式切换和输出执行的唯一写入者。
- Web 线程不执行硬件操作，不使用 LVGL 对象。

## 5. 启动与主循环

### 5.1 启动顺序

1. 建立安全输出：LED、加热为 0，双泵使用安全启动值。
2. 初始化数据库并合并默认配置。
3. 初始化 I²C、UART、PWM、RTC 和显示器。
4. 读取 DS3231；RTC 有效时立即允许日光节律运行。
5. 根据 `power_resume` 恢复运行模式和稳定目标值。
6. 启动 WiFi、Web、NTP 和 LVGL。
7. 进入 10 Hz 主循环。

`power_resume` 开启时：

- 恢复灯光/双泵/加热的模式和稳定目标。
- 自动灯光按当前 RTC 时间重新计算。
- 加热等待水温和水位有效后重新计算，不直接恢复旧占空比。
- 喂鱼不续行，重启后退出喂鱼并恢复水循环。

`power_resume` 关闭时使用数据库中的默认启动配置。

### 5.2 主循环

每 100 ms 执行：

1. 处理 LVGL/Web 已提交命令。
2. 读取水位并防抖；每秒读取 TDS、NTC、HDC1080。
3. 更新 WiFi、RTC、日光、双泵、加热和喂鱼状态。
4. 执行安全仲裁。
5. 原地更新渐变和 PWM 输出。
6. 发布 LVGL/Web 共用状态快照。
7. 保存变化项；每 60 秒保存传感器快照。
8. 喂主循环看门狗。

传感器数据超过 10 秒未更新视为失效。失效数值在 API 中使用 `null`，LVGL 显示 `--`。

## 6. 控制逻辑

### 6.1 灯光

- 4 路独立手动亮度和自动日光模式。
- 日光阶段：夜间 → 日出 → 日间 → 日落 → 夜间。
- 每个阶段保存开始时间和 4 路目标亮度。
- 当前时间位于过渡区间时线性插值，目标经过独立校准表后平滑输出。
- 手动模式不被日光任务抢回；切回自动时立即按当前时间计算。
- 在自动模式下调整任一 LED 亮度会切换为手动，避免目标被日光插值立即覆盖。
- 亮度设为 0 时允许完整关闭对应通道。
- DS3231 无效且 NTP 未校准时，使用默认/恢复的稳定亮度，并显示时间未同步。

### 6.2 水泵和气泵

- 每个泵有独立 `auto/manual` 模式、目标速度和实际速度。
- 自动模式使用保存的默认速度；手动模式使用用户目标速度。
- 喂鱼覆盖普通自动/手动目标。
- 正常运行期间接受平滑调速，避免速度突变。

### 6.3 喂鱼

- 默认时长 600 秒，可设置并持久化。
- 主页快捷键进入确认页，不直接启动，避免误触。
- 启动时保存双泵之前的模式和目标速度。
- 水泵、气泵目标均强制为 0。
- 喂鱼期间普通双泵命令不接管输出；重复启动不重置倒计时。
- 取消或倒计时结束恢复之前模式；自动模式重新计算目标。
- 灯光保持，加热和安全保护继续运行。
- 掉电重启不恢复喂鱼状态。

### 6.4 加热

- 使用 TDS 模块的 NTC 水温，而非环境温湿度。
- 自动模式根据目标温度、回差和输出上限计算 PWM。
- 手动模式允许设置输出，但仍受安全条件限制。
- 初版采用带回差的比例输出，不引入复杂 PID。
- 以下条件强制输出 0：水温无效、水温超过 10 秒未更新、低水位、水位组合异常、超过最高允许温度。
- 页面显示保护状态，用户命令不能绕过保护。

### 6.5 安全优先级

1. 安全保护。
2. 喂鱼对双泵的临时覆盖。
3. 手动模式。
4. 自动计划。

故障只限制相关输出，不使整个控制器停止。WiFi 断线、配网或 NTP 失败不影响底层控制。

## 7. RTC 与时间

- DS3231 为系统主时钟，地址 `0x68`，共享 I²C1。
- 启动读取 DS3231，有效后立即恢复日光节律，不等待 WiFi。
- STA 成功后执行 NTP，并用有效 NTP 时间校准 DS3231。
- NTP 失败保留 DS3231 时间。
- DS3231 无效时允许手动校时；手动时间可通过设置页写入 RTC。
- RTC 无效时标记 `time_valid=false`，不伪造日出日落时间。

## 8. 数据库

采用 Flash `/flash` 根目录下的 BTree 文件和字符串键值：

- `sysConfig.db`：WiFi、AP、断电续行、背光、自动回主页、默认喂鱼时长。
- `deviceConfig.db`：灯光、双泵、加热模式和目标值。
- `daylight.db`：日光阶段时间与 4 路亮度。
- `calibration.db`：4 路 LED PWM 校准表和泵/加热限制。
- `stats.db`：最近稳定运行状态和传感器快照。
- `logEvents.db`：保留少量关键状态/故障记录。

规则：

- 所有库统一使用一个 `thread.allocate_lock()` 保护。
- 键和值使用 bytes 写入，业务接口使用字符串。
- 不存在键时返回 `None`，不读取 `BTREE` 对象自身的属性/方法。
- 配置和稳定状态变化立即保存；传感器快照每 60 秒保存。
- 损坏数据库改名备份后恢复默认，不让启动流程崩溃。

## 9. WiFi 与配网

- 启动优先 STA，读取数据库中的 SSID、密码、加密策略。
- STA 断开由独立重连流程处理，避免重复并发重连。
- 配网失败进入配置 AP，同时保持鱼缸底层控制。
- AP 提供 SSID 扫描、密码输入、加密策略和保存。
- 配置 AP 无操作 300 秒后重启，防止永久停留配网状态。
- STA 成功后启动 NTP，Web 地址显示在设置页。
- WiFi/应用配置使用统一提交点，禁止后台线程直接改运行配置。

## 10. LVGL 设计

### 10.1 总体

- 固定 480×320 横屏，显示使用 MADCTL=`0x28`；触摸按 `X=raw_y、Y=319-raw_x` 转换。
- 像素格式为 `RGB565_SWAPPED`，SPI 直接透传，避免二次字节交换。
- 六页顺序：总览 → 灯光 → 设备 → 喂鱼 → 水质 → 设置。
- 使用横向 TileView 或等价滑动手势，不循环切换。
- 滑块、按钮和列表优先处理自身手势。
- 顶部状态栏显示时间、RTC、WiFi 和告警。

### 10.2 自动回主页

只有同时满足以下条件才返回：

```text
current_page != HOME 且 now - last_local_touch >= home_timeout
```

- 默认 `home_timeout=30` 秒，可配置。
- 主页不启动返回计时。
- 本地触摸、滑动、按钮和滑块操作重置计时。
- Web 操作不影响 LVGL 本地计时。
- 返回主页只改变显示，不停止后台任务。
- 未保存草稿不自动提交；返回时放弃并提示。

### 10.3 页面结构

- 总览：水温、TDS、水位、环境、灯光/双泵/加热摘要、告警、喂鱼快捷键。
- 灯光：自动/手动、4 路亮度、日光阶段、计划编辑。
- 设备：水泵、气泵、加热目标与实际输出、安全状态。
- 喂鱼：时长、确认、取消、倒计时、双泵锁定状态。
- 水质：TDS、电导率、水温、环境、水位原始/防抖状态、传感器健康。
- 设置：WiFi、RTC/NTP、断电续行、喂鱼时长、回主页时间、背光。
- 页面内容超过 270 px 时在页内纵向滚动，横向手势仍由 TileView 处理。

**组件规范**：

- **顶栏**：白底卡片 + 底部分隔线，左侧页名（`song_16`），右侧时钟 + WiFi（`montserrat_14`），底部 6 个页指示点（当前页 `C_PRIMARY`，其余 `C_MUTE`）。
- **指标卡 `_metric`**：白卡片内标题（`song_16`，`C_MUTE`）+ 大号数值（`song_24`，按指标上色）+ 底部圆角进度条；用于概览与水质页的关键读数。
- **分区卡 `_section`**：全宽、高度自适应的白卡片，首行分区标题；灯光/设备/喂食/设置页的内容分区。
- **状态药丸 `_chip`**：圆角背景 + 文字，运行/告警/失效等状态用 `C_OK/C_WARN/C_DANGER` 填充，待机用 `C_CARD_ALT`。

- **按钮**：主操作为实色 `C_PRIMARY` 白字，次操作为描边。
- 可触摸目标不小于 40 px；行高 38～52 px。
- 字体：中文用内置 `song_16/20/24`，数字/单位用 `montserrat_14`，不加载外部字库。

**交互约定**：

- 滑块仅在松手时提交；文本框聚焦时弹出 480×160 软键盘。
- 计划与设置草稿不自动提交；离开页面或自动回主页时放弃并提示。
- 顶栏状态行格式：`HH:MM:SS RTC:OK/-- WiFi:<ip|state> AL:<告警数>`。

### 10.5 性能与渲染约束（滑动流畅性保证）

UI 必须维持约 50 Hz 主循环（`TICK_MS=20`）且滑动跟手，以下约束不可回退：

- **只刷新可见页**：`_refresh` 按 `current_page` 分发到单个 `_refresh_*`，隐藏页不重建不重绘。
- **值未变不重设**：`_set_metric` / `_set_chip` / `_set_slider` / `_set_label_color` 均缓存上次值，相同则跳过 `set_text` / `set_style`，避免无谓失效与重绘。
- **滑动期间暂停刷新**：触摸按下（`_touch_down`）期间暂停数据刷新，松手恢复，保证滑动帧不被刷新抢占。
- **禁止每轮 `os.listdir`**：littlefs 遍历 `/` 耗时约 110 ms，会把主循环压到 ~5 Hz；截图请求改为每 500 ms 一次 `os.stat` 探测。
- 固件 LVGL 绑定差异：`arc.set_value` 只接受 1 个参数；`set_style_*` 必须带 selector（`lv.PART.MAIN` / `lv.PART.INDICATOR`）；`img` / `meter` / `btnmatrix` 不可用，图形化靠 `arc` / `bar` / 色块 / 符号字体实现。

## 11. 手机 Web

复用阅读灯项目的 Microdot 架构：

- `lib/microdot.py` 提供路由、请求解析和 `send_file` 响应。
- `_thread` 启动独立 Web 线程，`app.run(host='0.0.0.0', port=80)` 监听。
- `web/static/index.html` 为单页界面，内联 CSS/JS，不依赖外部资源。
- 请求线程只提交命令和读取快照，不直接访问 GPIO、PWM、数据库或 LVGL。
- 路由：`GET /`、`GET /static/<path>`、`GET /api/state`、`GET/POST /api/config`、`POST /api/command`、`GET /api/wifi/scan`、`POST /api/wifi/config`。
- 非法 JSON、无效命令和未知路径返回 JSON 错误，不向串口打印异常栈。

- 主要适配 360～430 px 手机竖屏，桌面端仅居中加宽。
- 顶部显示连接状态和告警，底部五个主导航：总览、灯光、设备、喂鱼、设置。
- 水质详情从总览进入。
- 单列卡片、触摸区域不小于约 44 px，不依赖 hover。
- 使用同一状态与命令接口，不实现独立业务状态机。

交互约定：

- 每 2 秒轮询 `/api/state`；`fetch` 失败时保留上次数据并显示错误条。
- 滑块和下拉框在 `change`（松手/选定）时提交，避免拖动期间刷写 Flash。
- 计划、系统设置、WiFi、RTC 编辑使用 dirty 标志，轮询不覆盖正在编辑的内容。
- 总览的“喂鱼”会先切到喂鱼视图并弹出确认；喂鱼期间相关控制禁用。
- 页面仅使用内联 CSS/JS，无外部 CDN、字体或图片依赖。

## 12. 异常与看门狗

- TDS/HDC1080/DS3231 初始化失败不阻止主循环。
- 每次重试间隔至少 5 秒，避免 10 Hz 循环重试卡死。
- 温度无效、水位异常只触发相关保护和告警。
- WiFi、Web、LVGL 任一部分失败不直接重启整个控制核心。
- 主循环健康推进时喂看门狗；后台线程运行不能代替主循环喂狗。
